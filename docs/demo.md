# 课程演示与交付

## 演示前准备

工程版入口为 `mail_assistant`，保留原型入口为 `mail_agent`。先构建网页，按[开发说明](development.md)启动，或按[部署说明](deployment.md)使用 Compose。需要解释实现细节时展示[主计划](plans/engineering-upgrade-plan.md)中的架构图和目录分层。

无账号演示使用独立目录：

```bash
.venv/bin/python -m mail_assistant --data-dir runtime/class-demo --port 8766 demo
```

打开 `http://127.0.0.1:8766` 并进入演示工作台。重复使用同一目录会保留摘要进度；重新演示首次体验时选择另一个新目录，避免覆盖已有资料。

样例模式运行实际网页、业务库、Worker、任务和 Agently TriggerFlow；正文及分析回答使用明确标记的规则样例。真实模型的摘要与工具调用需要另走联调，不能用样例回答证明模型效果。

## 网页演示顺序

1. **概览与摘要。** 展示两个来源、首份摘要的五项近期内容，解释三级优先级、行动、截止时间和依据。连续点击“刷新摘要”仍显示完整五项，并提示“已是最新，内容未变化”，不新增重复版本。说明最近 24 小时的确切起止范围、最后检查与内容更新时间；查看历史版本或重新分析。手动刷新不自动推送飞书。
2. **邮件依据与往来。** 打开会议时间更新，核对 16:00／B202，再打开引用关联的原通知查看 14:00／A301，返回更新邮件。同标题候选单独说明，不当作已确认会话。
3. **多轮查询。** 问“找导师的会议通知”，再问“后来有更新吗，最终时间和地点是什么”。展示工具／任务阶段、回答以及可点击的邮件来源。
4. **配置与状态。** 编辑邮箱，读取并选择文件夹；演示中文目录、不可选择的容器目录及读取重试。说明切换文件夹会重新确认观察范围，历史来源保留。
5. **缓存与连接生命周期。** 展示最近观察到、历史缓存、尚未确认三个状态；停用和移除连接分别操作。需要演示移除时添加专门的样例账号，确认后移除，保留原演示数据。
6. **后台执行。** 从任务记录查看同步、分析与发送的独立状态，刷新页面后继续查看任务。说明 API 负责交互，Worker 承担调度和长任务，关闭网页不停止后台。
7. **飞书入口。** 样例模式只展示引导界面。真实环境中由本人完成授权、权限／事件发布、配对和发送测试，再展示摘要及查询回复。发送失败重试既有投递，结果不确定时先核对。

## 真实联调数据

在专用测试邮箱中准备一封有明确截止时间的通知、一封无需处理的资讯和一组会议变更往来。往来使用邮件客户端正常回复形成引用头。QQ 与网易各保留至少一封测试邮件，并记录它们的来源、收件时间、正文和预期行动，便于人工核对。

验证模型的结构化输出和三个读取 Actions 后，再比较网页摘要与原文；记录漏项、无依据的判断、截止时间不明确时的行为及多轮来源。单次演示成功不代表一般准确率。邮件、模型、飞书及持续运行结果分别填入验收记录。

## 工程说明要点

- Agently 负责结构化分析和查询 Actions；TriggerFlow 编排固定摘要流程。
- 应用接口隔离模型与邮箱协议，Worker 经 MailboxProvider 调用只读 MCP；跨账号来源、缓存、时间覆盖和重试由应用管理。
- SQLite WAL、迁移、持久任务、配置版本与发送回执支撑重启恢复；生成摘要和发送摘要分开保存。
- React 工作台负责配置引导与操作反馈，网页和飞书复用业务服务并保留各自会话。
- Compose 分开运行 API 与 Worker，HTTPS 通过 Caddy；备份恢复和维护锁由命令行提供。
